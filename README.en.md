# Open ZCode Game Plugins

<p align="center">

A community-maintained catalog of **game-development plugins for ZCode and KayingCode**. This repository ships a machine-readable index (`catalog.json`), an inclusion spec, and a protocol that lets an Agent install plugins autonomously straight from GitHub. Plugin code remains owned by its respective authors.

> [!IMPORTANT]
> **This is not an official ZCode project, nor the official ZCode plugin marketplace.** It is not affiliated with, endorsed by, sponsored by, or otherwise connected to Z.AI / Zhipu AI or the ZCode maintainers. Being listed here does not mean being listed by ZCode officially. See [NOTICE](NOTICE).

> [!NOTE]
> Hosted at `kaying-ai/open-zcode-game-plugins`. Raw / clone / archive URLs in the catalog are derived from `GITHUB_REPOSITORY` (or the local `origin` remote); no manual editing is needed.

## Usage

### One prompt for your Agent (recommended)

Paste this into the ZCode / KayingCode Agent. It will fetch the catalog, filter, download, verify, and install:

```text
Read the plugin catalog at
https://raw.githubusercontent.com/kaying-ai/open-zcode-game-plugins/main/catalog.json
and pick a plugin that fits my host (zcode / kayingcode) and game-development task.
Then follow the catalog's "protocol" field and the repository's AGENTS.md to install it
locally and register it as a LOCAL marketplace source. Before installing, report the
plugin name, version, license and the exact target path. Never register a remote
marketplace URL, never run plugin-provided install scripts, and never overwrite an
already-installed plugin with the same name.
```

The Agent follows the **`github-to-local-source`** protocol: fetch from GitHub → place files in a stable local directory → register that directory as a **local source** in the host → install and enable. This is required because local-first hosts such as KayingCode.localrun **reject remote marketplace / CDN plugin packages**; simply pasting a GitHub URL into "Add marketplace" will be refused.

Full details:

- [AGENTS.md](AGENTS.md) — machine-readable install / contribution protocol for Agents
- [docs/INSTALL.md](docs/INSTALL.md) — human installation guide and manual fallback
- [docs/PLUGIN_SPEC.md](docs/PLUGIN_SPEC.md) — entry fields and inclusion criteria

### Manual quick start

```bash
git clone --depth 1 https://github.com/kaying-ai/open-zcode-game-plugins.git
cd open-zcode-game-plugins

# The first plugin is bundled, so no second download is needed
ls bundled/kaying-for-ui/zcode/marketplace.json
ls bundled/kaying-for-ui/kayingcode/marketplace.json

# In the host: "Plugin Marketplace -> Add" and paste the local absolute path:
#   ZCode       -> <repo>/bundled/kaying-for-ui/zcode
#   KayingCode  -> <repo>/bundled/kaying-for-ui/kayingcode
# then install and enable kaying-for-ui.
```

Tooling:

```bash
npm run validate   # validate all plugins/*.json and bundled package integrity
npm run build      # regenerate catalog.json + both README tables
npm run check      # CI mode: fail when generated files are stale (read-only)
```

> All scripts are zero-dependency Node (>= 18). **No `npm install` required.**

**Scope**: this repository maintains an index, a spec and a few bundled copies. It does not mirror official ZCode plugins, host official CDN assets, or run a remote marketplace service.

## Contributing

1. Fork and create a branch `plugin/<name>`.
2. Copy `templates/plugin.example.json` to `plugins/<name>.json`; fill in bilingual descriptions, hosts, license and a pinned source.
3. Run `npm run validate` and fix any reported errors.
4. Commit as `plugin: add <name> @ <version>` and open a PR using the checklist template.
5. CI validates the entry and previews the README row that will be generated.
6. **After merge, automation regenerates `catalog.json` and updates the plugin tables in both READMEs** — never edit them by hand.

See [CONTRIBUTING.md](CONTRIBUTING.md) (Chinese) for the full rules and the Agent-ready PR recipe.

Inclusion criteria: game-development focus, an explicit open-source license, support for at least one target host, a pinnable version, HTTPS sources, bilingual descriptions, and a verifiable manifest. One plugin per PR. Duplicates, uninstallable entries, unclear licensing, or undeclared executable scripts are rejected.
